# MT Model Training Pipeline

Fine-tune **Gemma-4 E2B-it** for machine translation (primarily Bangla → English) using **Unsloth** + **LoRA** (4-bit), track the run with **MLflow**, and export the result as a quantized **GGUF** model for `llama.cpp`.

## Overview

| Item | Value |
|------|-------|
| Base model | `unsloth/gemma-4-E2B-it` |
| Method | LoRA (r=16, alpha=16) on 4-bit quantized weights |
| Framework | Unsloth, TRL `SFTTrainer`, PEFT |
| Experiment tracking | MLflow (local file store) |
| Export format | GGUF (`q4_k_m`) |
| Task | Translation, output as JSON: `{"translated_text": "..."}` |

## Pipeline Flow

```
Raw CSV  ──►  DataLoader (clean)  ──►  80/10/10 split  ──►  train/validation/test .jsonl
                                                                   │
                      prompt template + JSON completion  ◄─────────┘
                                   │
                    Load Gemma-4 E2B (4-bit) + LoRA adapters
                                   │
                    SFTTrainer (custom collate, prompt masking)
                                   │
              ┌────────────────────┼─────────────────────┐
              ▼                    ▼                     ▼
        LoRA adapters        GGUF (q4_k_m)         MLflow metrics
```

## Requirements

- Linux with an NVIDIA GPU (CUDA 12.8 packages are pinned)
- Python 3.10+
- Key packages: `torch 2.10`, `unsloth 2026.4.8`, `transformers 5.5`, `trl 0.24`, `peft 0.19`, `bitsandbytes`, `datasets`, `scikit-learn`, `pandas`, `mlflow`

## Setup

```bash
python -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

Place the raw dataset in `Dataset/` (e.g. `AcceptedMachineTranslationData.csv`).

## Configuration

Paths and hyperparameters are currently **hardcoded**; edit them before running.

| File | Setting | Purpose |
|------|---------|---------|
| `utils/jsonL.py` | `INPUT_CSV`, `SPLITS_DIR` | Raw CSV location and where JSONL splits are written |
| `training.py` | `LORA_DIR`, `GGUF_DIR`, `MLFLOW_DIR` | Output locations |
| `training.py` | `MAX_SEQ_LEN=4096`, `BATCH_SIZE=4`, `GRAD_ACCUM=4` | Batch / sequence settings |
| `training.py` | `EPOCHS=10`, `LR=2e-4`, `WARMUP_RATIO=0.05`, cosine scheduler | Optimization |
| `training.py` | `GGUF_QUANT="q4_k_m"` | GGUF quantization method |
| `model_load.py` | `r=16`, `lora_alpha=16`, target modules | LoRA setup |
| all training scripts | `CUDA_VISIBLE_DEVICES="1"` | GPU selection |

## Usage

**1. (Optional) Clean the raw data**
```bash
python main.py
```

**2. Train** — this also generates the splits, fine-tunes, and exports LoRA + GGUF:
```bash
python training.py
```

**3. View experiment metrics**
```bash
mlflow ui --backend-store-uri file://<MLFLOW_DIR>
```

**4. Inspect the trained adapter**
```bash
python test_gguf.py
```

**5. Run the GGUF model** with `llama.cpp` (or `llama-cpp-python`) using the file in the `GGUF_DIR`.

## Data Format

**Input CSV columns used** (`data_processing.py`):

| Column | Meaning |
|--------|---------|
| `final_text_data` / `text_data` | Source text (`final_text_data` preferred, falls back to `text_data`) |
| `final_text_version` | Target (reference) translation |
| `source_language`, `target_language` | Language names |

**JSONL record** (one per line):
```json
{"source": "...", "target": "...", "source_language": "Bangla", "target_language": "English"}
```

Split: 80% train / 10% validation / 10% test (`random_state=42`). Current split sizes: ~3,883 train / 486 validation / 485 test.

## Prompts

Templates live in `prompts/`. Training uses `get_simple_translation_prompt` from `prompts/simple_prompt.py`. Other variants include SOP-based prompts (`bn_to_en_withSOP.py`, `multilingual_SOP.py`), context-aware, accuracy- and fluency-focused versions. SOP prompts encode rules such as proper-noun handling, administrative terminology, tense/voice, British spelling, and formal register for job circulars.

## Model & Training Details

- **Quantization**: 4-bit load, `max_seq_length=4096`
- **LoRA targets**: `q_proj, k_proj, v_proj, o_proj, gate_proj, up_proj, down_proj`
- **Gradient checkpointing**: Unsloth mode
- **Loss masking**: prompt tokens (and padding) are set to `-100`, so loss is computed only on the JSON completion
- **Precision**: bf16 if supported, otherwise fp16
- **Eval / save**: every epoch; best model loaded at end
- **Thinking mode** disabled for Gemma chat template
